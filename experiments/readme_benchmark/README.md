# README 기반 새 테스트

현재 사용자 요청에 따른 Ollama·vLLM 재테스트는 **[readme_serving_retest](readme_serving_retest/README.md)**에서 실행한다. README 검증 목적에 맞춘 새 합성 질문 500쌍×10개와 목적별 통제 21개를 사용하며, 요청한 후보별 16개 로그 필드를 기록한다. 실행 상태와 완료 보고서는 해당 폴더에 저장한다. 아래의 과거 실행 결과와 질문셋은 보존하며 이번 재테스트에 재사용하지 않는다.

새 테스트의 코드, 데이터, 실행 결과는 이 폴더 안에 둔다. 기존 프로젝트의 테스트와 결과는 기존 위치에 보존한다.

기준 문서는 사용자가 제공한 최신 README 원문 (로컬 전용: `data/requested_readme.md`)이다. 이후 사용자 지시에 따라 원문의 기존 테스트 재사용·회귀 테스트 항목은 적용하지 않는다. 기존 테스트 질문, 분류 비율, 정답 라벨, 모델 선정 결과, 임계값을 새 평가에 가져오지 않는다.

- `data/`: FAQ 원문에서 추출한 검색 코퍼스, 입력 출처, 새 문항 작성 자료.
- `scripts/`: 새 데이터 작성과 검증 코드.
- `outputs/run-v1/`: 이번 새 평가셋의 모델·엔진·장치 테스트 결과.

FAQ 원문은 사실과 검색 문서의 근거로만 사용한다. 새 문항 603행과 반복 실행 40행을 작성했고, 반복을 제외한 고유 query 문자열은 544개다. 55개 사실 작성 seed의 변형을 포함하므로 모든 행을 독립 관측으로 보지 않는다. 독립 정답 검수는 아직 끝나지 않았다. 이전 작업에서 기존 테스트를 열람한 이력은 있으므로 완전한 블라인드 작성이라고 주장하지 않는다.

## 실행 구성

이 폴더에서 `docker compose`를 실행한다. 부모 폴더의 compose와 기존 테스트 runner는 이번 실험에 사용하지 않는다. 컨테이너에는 이 폴더만 읽기 전용으로 연결하고 `outputs/`만 쓰기를 허용한다. 고정 모델 가중치와 Docker 이미지는 재사용하며 기존 테스트 데이터는 연결하지 않는다.

- `run_quality.ps1`: 신규 입력 검증, A/B/C, BGE/Jina×질문/질문+답변 네 reranker 조합, 조건부 E/F, 새 calibration 선정과 holdout, 분리 진단.
- `run_serving.ps1`: Ollama→TEI→vLLM 각각 켜기·확인·측정·끄기·종료 확인. concurrency 1/4/8/16/32 × 요청 batch 1/8/32.
- `run_hardware.ps1`: 엔진 비교와 일치 검사를 마친 뒤 별도 CPU/GPU component 비교.

입력과 선정 결과를 해시로 동결한다. 이미 완료한 holdout은 다시 실행하지 않는다. Jina 이미지의 패키지 import 오류는 검색 실행 전에 발생했고, 고정 BGE CLS+L2 로더로 수정한 뒤 calibration 벡터와 일치하는지 확인해 첫 holdout을 완료했다. 이 이력은 `outputs/run-v1/holdout/infrastructure_failure.json`에 남겼다.

실제 서비스 실패 로그가 없는 REAL_FAILURE와 정책 버전·유효기간이 없는 TEMPORAL_VERSION은 0건으로 기록했다. 문서 공격은 검색·실제 Context 구성까지만 측정했으며 생성 모델의 행동, 개인 조회 API 실행, 명확화 정책은 이번 범위에서 미실행이다.

## 현재 결과

일반 holdout Hit@3은 90.61%, 조건 문항 Hit@3은 97.66%다. 거절 정책을 적용하면 일반 유효 Hit@3은 85.95%다. NO_FAQ F1은 0.48이며 정답 없는 10행 중 4행을 잘못 채택했다. 정답 라벨의 독립 검수가 필요하므로 제품 적용 확정 결과로 사용하지 않는다.

Ollama·TEI·vLLM은 각 15개, 총 45개 부하 조건에서 17,109요청을 실행했으며 실패 요청은 0건이다. 엔진마다 켜기·확인·측정·끄기·종료 확인을 완료했다. 세 엔진 모두 사전에 정한 corpus/query cosine 최솟값 0.9999 기준을 통과하지 못해 엔진 후보를 확정하지 않았다. 비교 질문 50개의 Top-1은 기준과 모두 같았다. 이 결과로 벡터 일치 기준을 사후에 낮추지 않는다.

별도 CPU/GPU는 동일한 float32 dense component로 batch 1/8/32를 각각 30회 측정했다. 벡터 cosine 최솟값은 0.99999988로 일치 검사를 통과했다. batch 32 처리량은 CPU 6.64 texts/s, GPU 92.67 texts/s다. 전체 retrieval+reranker 엔진의 종단 성능이나 장시간 안정성 결과로 해석하지 않는다.

원시 결과와 한영 비교·실패 분석은 `outputs/run-v1/`에 저장했다. 완료한 단계와 미실행 범위는 실행 보고서 (로컬 전용: `outputs/run-v1/실행결과.md`)에 정리했다. 동결 입력 해시와 완료 여부는 `completion_audit.json`, 종료 확인은 `final_shutdown.json`, 결과 파일의 해시는 `artifact_inventory.json`에서 확인한다. 최종 확인 시 활성 테스트 컨테이너는 0개다.

## 추가 요청: 원본 3,000쌍당 변형 10개

이후 사용자가 지정한 3,000쌍 각각에 변형 10개를 생성하도록 요청한 작업은 [variations_30000](variations_30000/README.md)에 별도로 저장했다. 총 30,000행이며 원본 15개 분류를 각각 2,000행으로 유지했다. 앞의 603문항 실험과 결과는 그대로 보존한다. 이번 요청에 따라 지정 원본의 질문·정답을 작성 기반으로 사용했으며 기존 실험 결과와 임계값은 재사용하지 않았다. 질문·정답의 독립 의미 검수와 새 검색 성능 평가는 미완료다.

## 추가 실행: 30,000행 전체 엔진별 Calibration

생성한 30,000행 전체의 Ollama·vLLM·TEI별 A~F 구조 비교는 [engine_calibration_30000](engine_calibration_30000/README.md)에서 별도로 진행한다. 엔진당 11개 구조를 실행하며 각 서빙 엔진의 실제 dense HTTP 결과를 사용한다. 기존 603문항 및 원본 3,000문항 실행 결과는 재사용하지 않는다. 512토큰 초과 2,340행도 길이 설정을 늘려 자르지 않고 입력한다. 이 실행은 Calibration 전용이며 독립 의미/정답 검수·Holdout·생성/API 동작 평가는 포함하지 않는다. 완료 여부는 해당 폴더 `outputs/run-v1/completion_audit.json` 생성으로 확인한다.

## 새 원천으로 교체한 변형 데이터

사용자가 이후 제공한 `faqs.jsonl` 기반의 새 3,000쌍×10개 문항은 [faqs_based_30000](faqs_based_30000/README.md)에 분리했다. 이전에 생성한 질문·정답을 작성 원천으로 사용하지 않는다. 새 파일의 브랜드·카테고리·언어 분포를 보존하고 검증 목적, 한영 대응어 변형, 근거 ID를 연결한다. 독립적인 의미·정답 검수와 NO_FAQ 음성 문항 검수는 미완료다. 앞의 30,000행 Calibration은 사용자의 중지 요청에 따라 일시 중지된 상태이며 이 데이터 생성 요청으로 재개하지 않는다.

이후 요청한 새 FAQ 데이터의 Ollama·vLLM 전체 구조 비교는 [faqs_engine_ollama_vllm_30000](faqs_engine_ollama_vllm_30000/README.md)에 별도로 실행한다. 본 평가 30,000행과 별도 원문 기준 3,000행을 엔진당 11개 구조에서 실행하고 엔진 기동·측정·종료를 확인한다. TEI와 이전 Excel 데이터 실행은 포함하지 않는다. NO_FAQ가 없어 거절 임계값은 적합하지 않고 순위와 점수 분포를 비교한다.

현재 해당 30,000행 실행은 사용자 중지 요청에 따라 보존 중이다. Ollama A/B/C와 BGE 질문 reranker만 완료했고 질문+답변 조합은 체크포인트에서 중지했으며 vLLM은 시작하지 않았다. JSON 기반 500쌍 축소 입력은 준비만 했고 실행하지 않았다. 이후 원천을 기존 3,000행 Excel로 바꾸고 원문 README에 맞게 설계를 재정렬한다. [README 대비 차이와 수정 기준](faqs_engine_ollama_vllm_5000/README.md)에 사용자 변경 사항과 구현 가정을 구분해 기록했다. 자동 실험 runner는 현재 재개하지 않는다.

이후 사용자 지시에 따라 질문의 내용과 유형 선정은 README의 검증 목적만 기준으로 한다. 기존 15개 분류의 균등 비율과 모든 쌍에 같은 10종 변형을 적용하던 규칙을 제외했다. [현재 질문 작성 규칙](readme_purpose_questions/README.md)에 검증 목적·변형 요소·보존 조건·사실 GT·실패 기준과 실행 그룹을 정의했다. FAQ 원문에서 근거를 연결한 예시를 함께 작성했으며 500쌍 전량 생성과 새로운 서빙 실행은 아직 완료된 상태가 아니다.
