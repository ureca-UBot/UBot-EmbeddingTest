# 새 faqs.jsonl 기반 3,000쌍 × 10개

사용자가 새로 제공한 `1-faqs.jsonl`만 질문·답변 원천으로 사용한다. 이전 Excel 평가셋, 이전에 생성한 테스트 질문·정답, 검색 결과·벡터·임계값은 가져오지 않는다. 실험 설계는 사용자가 제공한 최신 README를 따른다. 기존 폴더와 중지한 Calibration 결과는 보존한다.

결과는 **3,000쌍, 쌍당 서로 다른 변형 10개, 총 30,000행**이다. 검토는 전체 질문 검토 화면 (로컬 전용: `outputs/질문_30000행_검토.html`)에서 브랜드·태그·언어·질문으로 검색할 수 있다. 전체 문항 JSONL (로컬 전용: `data/variations.jsonl`), 모델 입력 전용 JSONL (로컬 전용: `data/model_inputs.jsonl`), 선택 원천 3,000쌍 (로컬 전용: `data/source_pairs.jsonl`), 검색 코퍼스 (로컬 전용: `data/corpus.jsonl`)를 각각 분리했다. 문항에 지정한 FAQ ID로 코퍼스를 조회하면 원문 답변과 원천 ID를 확인할 수 있다.

## 원천 정리와 표본 선정

`source/faqs.jsonl`은 첨부 파일의 바이트를 그대로 복사한 스냅샷이다. SHA256은 `76d867e4b4e183e6b52c8edfb31ec7da4e74f8495b4a2a2ce10fb2472ecf8a2d`다. 원천 3,365건 중 텍스트 답변이 있는 항목은 3,356건이다. 같은 브랜드에서 공백을 정규화한 질문·답변이 모두 동일한 항목을 묶어 3,248쌍으로 만들었다. 중복 108건의 원천 ID는 대체 가능한 정답 ID로 보존한다.

이미지로만 답하는 9건은 텍스트 답변을 추정하지 않는다. 답변에서 질문을 추정한 2건은 코퍼스와 생성 대상에서 제외한다. 같은 브랜드에서 동일 질문의 답변이 여러 개인 7그룹·17원천건은 생성 seed에서 제외한다. 이 그룹의 15개 서로 다른 질문·답변 쌍은 코퍼스에 검토 플래그와 함께 남겨 실제 경쟁 문서로 유지한다. 상세 이유는 원천 검토 목록 (로컬 전용: `data/source_review.jsonl`)에 있다.

검색 코퍼스는 3,246쌍, seed 후보는 3,231쌍이다. seed의 브랜드·카테고리·언어 조합 244개를 모두 한 건 이상 포함하고 나머지 표본은 비율에 따라 배분한다. 동일 층에서는 고정 SHA256 순서로 선택한다. 선택된 한국어 원천은 2,899쌍, 영어는 101쌍이다. 원천의 15유형 라벨은 이 파일에 없으므로 기존 평가셋의 분류를 강제로 붙이지 않는다.

| 브랜드 | seed 후보 | 선택 쌍 | 변형 행 |
|---|---:|---:|---:|
| KT | 1,090 | 1,016 | 10,160 |
| LG U+ | 127 | 117 | 1,170 |
| SKT | 1,301 | 1,207 | 12,070 |
| U+유모바일 | 431 | 402 | 4,020 |
| 아이즈모바일 | 186 | 170 | 1,700 |
| 이지모바일 | 96 | 88 | 880 |
| 합계 | 3,231 | 3,000 | 30,000 |

층별 후보·선택 수와 비율 오차는 선정 분포 (로컬 전용: `data/strata_distribution.json`)에 기록한다. 비율의 기준은 중복·품질 문제를 정리한 seed 후보이며 원본 중복 행의 비율을 그대로 복제하지 않는다.

## 쌍마다 생성한 열 가지 변형

| 슬롯 | 변경 요소 | 유지할 근거 |
|---|---|---|
| V01 | 정중한 문장·문법 변형 | 원천 한 쌍 |
| V02 | 구어체·문의 표현 | 원천 한 쌍 |
| V03 | 대괄호 상품 주제 위치 또는 문의 표현 | 원천 명칭과 한 쌍 |
| V04 | 적용 가능한 한영 대응어 한 개 | 의도·수치·조건·한 쌍 |
| V05 | 여러 한영 대응어 또는 대응어와 문장 변형 | 의도·수치·조건·한 쌍 |
| V06 | 해석 가능한 작은 오타·띄어쓰기 | 숫자·상품 라벨·한 쌍 |
| V07 | 숫자/단위 표기, 조건 강조, 문의 표현 | 값·단위·비교 연산자·한 쌍 |
| V08 | 긴 배경 뒤에 덧붙임, 핵심 질문은 앞 | 원천 한 쌍 |
| V09 | 긴 배경 앞에 배치, 핵심 질문은 뒤 | 원천 한 쌍 |
| V10 | 같은 브랜드·언어의 실제 질문 두 개 결합 | **서로 다른 두 FAQ 모두** |

V04/V05는 대응어가 실제 질문에 있을 때만 `KR_EN_EQUIVALENT`로 지정한다. 한영 변형은 1,365쌍에서 2,730행이다. 대응어가 없는 슬롯은 다른 문의 표현으로 생성하고 `no_applicable_equivalent_term`을 기록한다. 전 문장 번역과 새로운 상품 별칭을 임의로 만들지 않는다. eSIM과 USIM을 서로 치환하지 않는다. 문장 전체가 같은 뜻인지의 독립 검수는 아직 완료되지 않았다.

브랜드를 모든 입력에 명시해 여러 사업자의 정책이 섞이는 상황을 통제한다. 짧은 제목이나 `the card`처럼 대상이 생략된 원문에는 원천 카테고리를 사용자 입력의 범주로 명시하고 `added_user_scope`에 남긴다. 복합 질문의 동반 질문에도 필요한 범주를 명시한다. 이 범주는 GT ID나 정답이 아니라 **통제된 사용자 문맥**이다. 실제 사용자의 무범주·무브랜드 입력 일반화 성능으로 해석하지 않는다.

모든 변형은 규칙 기반 초안이다. 요청 문구만 바뀐 경우를 깊은 의미 변형으로 주장하지 않고 `change_trace`와 `deep_paraphrase`로 구분한다. 검증 목적별 실제 태그 수와 미충족 범위는 검증 목적 목록 (로컬 전용: `data/purpose_catalog.json`)에 있다. 부정·숫자·조건은 원문에 실제 있을 때 태그를 추가한다. 반대 조건으로 질문을 바꾸고 기존 정답을 그대로 상속하지 않는다.

## GT, 입력, 분할

`variations.jsonl`은 평가 메타데이터이고, 모델에는 `model_inputs.jsonl`의 `query` 문자열만 전달한다. `case_id`, `brand`, `evaluation_family`는 runner 관리 필드다. FAQ ID·원천 URL·정답·검증 태그를 모델 입력으로 이어 붙이지 않는다. 한영 비교의 기준 입력은 paired_baselines.jsonl (로컬 전용: `data/paired_baselines.jsonl`)에 별도로 고정하며 30,000행에 중복 집계하지 않는다.

`required_facts`의 현재 단위는 `FAQ_SUPPORT_BUNDLE`이다. 자동 상속한 원문 질문·답변 묶음이며 **독립 검수된 원자 사실 GT가 아니다**. FAQ Hit/MRR, 필요한 FAQ 모두 검색했는지의 진단은 가능하다. 원자 FactRecall/AllFactsHit 결과로 보고하려면 답변에서 실제 필요한 사실을 별도로 검수해야 한다. 개인정보 조회·API 실행·생성 응답 성공 여부도 이 데이터의 검색 라벨과 분리한다.

V10의 두 질문을 연결한 부모들은 같은 `split_group_id`로 묶었다. 그룹은 1,498개다. 향후 calibration/holdout을 나눌 때 부모 행 단위로 나누면 동반 질문이 누출될 수 있으므로 이 그룹을 통째로 배정해야 한다. 현재 split은 미배정이며 holdout 실행 이력이 없다.

## 길이와 경쟁 문서 준비

캐시된 BGE-M3·BGE reranker·Jina reranker 토크나이저로 30,000행을 자르지 않고 검사한다. 원문 질문·답변은 corpus_views.jsonl (로컬 전용: `data/corpus_views.jsonl`)에 전체를 유지한다. 긴 답변용 reranker_chunks.jsonl (로컬 전용: `data/reranker_chunks.jsonl`)은 FAQ 질문과 답변 창을 합쳐 문서당 최대 256토큰, 답변 겹침 최대 32토큰으로 준비한다. 원문 문자 범위와 해시를 남기며 모든 답변의 문자 구간을 빠짐없이 덮는다.

이 창은 선택 가능한 reranker 입력 준비물이다. 실제 구조 비교 전에 전체 문서/창 사용 정책과 창 점수를 FAQ 점수로 합치는 규칙을 고정해야 한다. 창마다 별도 FAQ로 세지 않는다. 실행 전 각 엔진의 실제 토크나이저·길이 설정도 대조해야 한다. 검사 결과는 토큰 검사 (로컬 전용: `outputs/token_audit.json`)에 있다.

경쟁 FAQ 후보 (로컬 전용: `data/hard_negative_candidates.jsonl`)는 이번 코퍼스의 질문만으로 char TF-IDF를 계산해 부모별 같은 브랜드 3건과 다른 브랜드 2건을 연결한다. **검수된 오답으로 지정하지 않았다.** 답변이 다르거나 브랜드가 다르다는 이유만으로 HARD_NEGATIVE를 확정할 수 없다.

## 완료 범위와 남은 검수

30,000행 생성, 원천 출처·ID·중복 대체 ID 보존, 분류 포함 여부, 모델 입력 분리, 숫자·명칭·부정·비교 조건 보존, 분할 연결, 답변 창의 전체 포함 여부를 자동 검증한다. 결과는 validation.json (로컬 전용: `outputs/validation.json`), 산출물 해시는 artifact_inventory.json (로컬 전용: `outputs/artifact_inventory.json`)에 기록한다.

독립적인 의미·정답 검수, 원자 사실 주석, 실제 실패 로그, 정책 버전 GT, 문맥 rewrite, 생성/API·문서 공격 실행은 미완료다. NO_FAQ를 자동으로 꾸며 넣지 않았다. 따라서 이번 긍정 문항만으로 NO_FAQ precision/recall/F1이나 거절 임계값을 확정하지 않는다. 임계값 fit 전에 코퍼스 부재를 검수한 음성 문항이 필요하다. 이번 요청에서는 Ollama·vLLM·TEI 측정과 중지된 Calibration을 재개하지 않는다.

## Docker 재생성

이 폴더에서 실행한다. 컨테이너에는 이번 폴더만 연결하며 원천·코드는 읽기 전용, `data`와 `outputs`만 쓰기를 허용한다. 네트워크·GPU·서빙 포트를 사용하지 않는다. 기존 이미지와 토크나이저 캐시는 소프트웨어 의존성으로만 사용한다.

```powershell
docker compose run --rm --no-deps dataset
```

이 명령은 이번 폴더의 생성 산출물을 다시 작성한다. 원천 스냅샷·원래 테스트 폴더·이전 Calibration 산출물은 수정하지 않는다. 원천 SHA256이 바뀌면 생성기는 중단한다.
