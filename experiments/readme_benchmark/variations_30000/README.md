# 원본 3,000쌍의 변형 질문 30,000행

사용자가 선택한 원본 `FAQ_RAG_15개항목_각200건_총3000건_피드백수정본(1).xlsx`의 질문·정답 3,000쌍을 기반으로, 각 원본에 서로 다른 변형 질문 10개를 작성했다. 기존 603문항 실험의 질문·정답 라벨·임계값·검색 결과는 가져오지 않았다. 원본 파일과 기존 결과를 수정하지 않았다.

## 생성 결과

- 변형 30,000행, 원본 15개 분류별 2,000행. 각 원본 내의 10개 질문은 모두 다르다.
- 고유 질문 문자열은 22,073개다. 원본 유형 간 동일 질문과 반복 테스트는 삭제하지 않았다.
- 원본 RT 200행은 변형 후 2,000실행 행이다. 변형 입력 200개를 각각 10회 동일하게 실행할 수 있도록 회차와 입력을 보존했다.
- 한영 동등어 변형 5,766행. 원본 한국어 질문과 대응어 치환 질문을 `language_pairs.jsonl`에서 연결한다. 전체 문장의 영어 번역이 아니라 한국어·영어 용어 혼용 질문이다.
- 문서 공격 fixture 66개. AD의 정상 질문과 기존 공격 문구를 분리해, 공격을 시험용 FAQ 문서에 넣었다. 정상 FAQ 사실은 보존하고 서비스 코퍼스는 변경하지 않았다.
- 실제 실패 로그를 요구하는 REAL_FAILURE는 0행이다. TEMPORAL_VERSION 1,200태그 행은 원본 CF의 **가상 시행일·정책 버전**을 사용하는 사례이며 실제 정책 이력이라고 주장하지 않는다.

## 변형 방법

기본 구성은 문장·어휘 재작성 4개, 해당되는 한영 대응어 변형 2개, 오타·띄어쓰기 변형 1개, 원본 검증 목적에 따른 표기·구조 변형 1개, 긴 질문의 앞·뒤 위치 변형 2개다. 같은 문장이 겹치면 다른 실제 어휘·요청형 문장으로 재작성한다. 대응어가 없는 질문은 다른 문장 재작성으로 대체하며 한영 태그를 붙이지 않는다.

다중 의도는 질문 순서를 바꾸되 요구를 모두 유지한다. 수치·기준 시각·상품명·API 상태·조건 주체는 보존한다. 숫자 쉼표와 GB/MB 단위 표기를 바꿔도 같은 값과 단위를 뜻한다. 부정 표현을 바꿀 때 극성을 뒤집은 뒤 원래 정답을 복사하지 않는다. 긴 질문에는 무관한 배경을 넣어 핵심 질문 위치를 앞과 뒤로 구분한다.

작성 방식은 원본에 적용 가능한 규칙과 작성자가 구성한 대응어 사전이다. 생성형 언어 모델을 호출하지 않았다. 실행 중 전달되는 모델 입력은 변형 질문과 고정 원본 대화 이력이며, 정답·제공 Context·추적 FAQ ID·사용자/API fixture·페르소나 지시는 검색 질문에 넣지 않는다.

## 정답과 평가 범위

정답 예시·필수 사실·기대 상태·처리 경로는 원본의 의미와 조건을 보존하는 변형에 상속했다. 원본의 정답 예시는 제공 Context·사용자/API·페르소나에 의존할 수 있으므로 `source_fixture_id`로 전체 원문 fixture를 연결해야 한다. 추적 FAQ ID는 원문 연결용이며 검수 완료된 atomic fact 정답 집합과 다르다.

원본의 NO_ANSWER_TOPIC 부재 판정, 문맥에 따른 지시어 해석, 대응어 의미, 변형별 정답 적합성은 독립 검수가 필요하다. `annotation_status`는 모든 행에서 독립 의미·정답 검수 필요 상태다. 자동 검사 통과를 의미 검수 완료로 표시하지 않았다. train/calibration/holdout 분할과 성능 테스트는 실행하지 않았다. 이후 분할할 때 원본의 변형, 동일 질문, 반복 회차, 공유 근거에 따른 연결을 고려해야 한다.

DOCUMENT_ATTACK 행은 `document_attack_fixtures.jsonl`의 별도 Context를 로드하는 통제된 실험용이다. 일반 FAQ retrieval만 실행하고 문서 공격을 평가했다고 보고할 수 없다. 원본 CF의 가상 버전, API 응답, 빈 Context 등 생성 진단도 같은 방식으로 해당 fixture를 사용해야 한다.

## 파일

- `data/variations.jsonl`: 실행용 30,000행, 원본 ID·검증 목적·변경 내역·정답·근거·고정 이력·반복 그룹 포함.
- `data/source_pairs.jsonl`: 원본 3,000행의 전체 27개 필드. Context·대화·사용자/API·페르소나를 포함한다.
- `data/language_pairs.jsonl`: 한국어 원본과 한영 대응어 변형의 연결.
- `data/document_attack_fixtures.jsonl`: 실제 원본 공격 문구를 문서로 옮긴 별도 시험 Context.
- `data/purpose_catalog.json`, `data/lexicon.json`: 설계의 16개 목적과 대응어의 작성 기준.
- `data/manifest.json`: 원본 출처·해시, 개수, 목적·분류 분포, 생성 방식, 검수 상태.
- `outputs/FAQ_3000쌍_각10개_변형질문_30000행.xlsx`: 질문 검토용 Excel. 변형, 검증 목적, 원본 질문·정답을 나눠 표시한다.
- `outputs/validation.json`: 30,000행 전체의 연결·중복·수치·시각·상품명·API 상태·반복 입력 검사 결과.
- `outputs/token_length_summary.json`: 실제 BGE-M3 토크나이저로 측정한 질문 길이와 512토큰에서 핵심 질문 보존 여부. 실제 서빙 잘림 동작 측정과 다르다.
- `outputs/review_samples.jsonl`: 유형별 원본 2개씩, 각 10개 변형의 문장 검토 자료 300행.

## 재현

이 폴더에서 네트워크가 차단된 별도 Docker 컨테이너를 사용한다. GPU 검색·서빙 컨테이너를 켜지 않는다. 모델 캐시는 토큰 길이 검사에만 읽기 전용으로 사용한다.

```powershell
docker compose run --rm dataset
docker compose run --rm dataset scripts/validate_variations.py
docker compose run --rm dataset scripts/test_contracts.py
docker compose run --rm dataset scripts/audit_token_lengths.py
```

현재 데이터 전체 검사와 변형 규칙 계약 테스트 6개가 통과했다. Excel은 JSONL의 검토용 표현이며 Excel에서 수정한 검수 결과가 JSONL에 자동 동기화되지는 않는다. 원시 데이터와 출처 해시를 유지한 상태에서 별도 버전으로 검수를 반영한다.

길이 측정에서는 긴 질문 6,000행 중 2,340행이 512토큰을 넘었고 최대 길이는 602토큰이었다. 512토큰까지만 보존하면 핵심 질문이 온전히 남지 않는 1,194행을 기록했다. 이들은 길이·위치 진단 사례로 구분해야 한다. 실제 엔진의 거절·잘림·처리 성공 여부는 이번 생성 작업에서 실행하지 않았다. Excel의 목적별 행 수는 생성 시 `data/manifest.json` 집계이며, 이후 셀 수정에 따라 자동 갱신되는 값으로 표시하지 않았다.
