# FAQ 평가셋 v2

사용자 선택인 **문항 수보다 품질·목적 균형 우선**에 따라 새로 작성한 331문항이다. 기존 5,021문항과 측정 결과는 보존한다. 원천은 사용자가 선택한 엑셀의 `FAQ 원문`에서 추출한 FAQ 1,024건이며, 이전 테스트 질문이나 모델별 성적을 생성 입력으로 사용하지 않았다. 기존 질문은 완성된 문항의 중복 검사에만 읽었다.

현재 상태는 **작성자 근거 확인과 구조 검증을 마친 합성 검수본**이다. 독립적인 의미·대체 정답·정답 부재 검수는 미완료다. 완전히 공정한 평가셋이나 운영 트래픽 대표 표본으로 선언하지 않는다. v2 모델 추론이나 임계값 재피팅도 아직 실행하지 않았다.

- 질문·근거 검수 화면 (로컬 전용: `review/index.html`) — 전체 코퍼스도 열람 가능
- 전체 문항 JSONL (로컬 전용: `data/cases.jsonl`), 사실별 근거 (로컬 전용: `data/facts.jsonl`)
- 분포·누수 검사 (로컬 전용: `data/audit.json`), 15개 검증 결과 (로컬 전용: `data/validation_report.json`)
- 입력 및 데이터 해시 (로컬 전용: `data/manifest.json`), 실험 규칙 (로컬 전용: `protocol.json`)

## 이전 편향을 줄인 부분

1. 원문 FAQ 질문을 앞뒤에 붙이는 생성 방식을 없앴다. 문장부호·공백을 제거한 원문 질문 포함과 이전 5,021개 검색 입력의 완전 중복은 모두 0건이다. 다만 이 검사는 독립 의미 검수나 의미적 중복 제거를 대신하지 않는다.
2. FAQ당 10개를 일률적으로 채우지 않는다. 분야별 핵심 사실 6개를 먼저 잡고, 적용 가능한 언어·오타·배경·조건 대조를 별도 연결했다.
3. NO_FAQ는 같은 종류의 비용 질문 두 개에 의존하지 않는다. 34개 서로 다른 부재 후보 중 31개는 가까운 서비스 주제의 누락 사실, 1개는 없는 상품, 2개는 업무 범위 밖이다. 영어·혼합 변형을 독립 부재 근거로 추가 계산하지 않는다.
4. 질문 일부에 답할 수 있으면 PARTIAL로 둔다. 질문 정보가 부족하면 CLARIFY 대상으로 둔다. 두 상태를 NO_FAQ로 합치지 않는다. 개인 계정 조회가 필요한 항목을 임의로 NO_FAQ에 넣지 않았다.
5. 전체 답변 하나를 사실 하나로 두는 대신 가격·제공량·조건을 필요한 범위에서 분리했다. 같은 사실을 담은 다른 FAQ는 사실별 대체 정답으로 연결한다. 문자 유사도 검수 후보는 대체 정답으로 자동 승격하지 않는다.
6. 실제 FAQ 질문에 답이 없을 수도 있다. 예를 들어 FAQ-775는 가족 위치 알림의 등록 방법만 설명하고 최대 등록 인원을 답하지 않는다. 문서 제목이 비슷하다는 이유로 최대 인원 질문을 정답 있음으로 처리하지 않는다.
7. 문맥 질문은 사용자 이전 발화와 현재 발화를 따로 저장한다. 모든 검색 구조가 동일한 고정 재작성문을 쓰며, 재작성문에 정답을 덧붙이지 않는다. 현재 발화만 있을 때의 모호성 문항은 별도 상태다.

## 분할

| 분할 | 전체 | FAQ 있음 | NO_FAQ 행 | 서로 다른 NO_FAQ 후보 | PARTIAL | 정보 부족 |
|---|---:|---:|---:|---:|---:|---:|
| development | 155 | 98 | 37 | 17 | 10 | 10 |
| calibration | 85 | 63 | 15 | 9 | 3 | 4 |
| holdout | 91 | 68 | 16 | 8 | 4 | 3 |

NO_FAQ를 포함한 연결 그룹은 전체 33개이며 development/calibration/holdout에 각각 16/9/8개다. 서로 다른 부재 사실 34개도 모두 통계적으로 독립이라고 가정하지 않는다. 실제 calibration 피팅 대상은 미검수 진단 기준 64행(FAQ 49, NO_FAQ 15)이며 나머지는 상태·트랙 기준으로 제외한다.

세 분할 모두 **17개 분야의 정답 있음 문항과 15개 주 목적**이 들어 있다. 50/25/25는 목표 비율이며, 연결 그룹을 쪼개지 않으므로 실제 행 수는 정확히 일치하지 않는다. 같은 사실, 대체 정답 FAQ ID, 정책 묶음, 언어·오타·길이·문맥·조건 대조쌍, 동일 부재 사실은 분할 사이에 걸치지 않는다. 이는 등록된 연결 관계에 대한 검증이며, 누락된 의미적 별칭까지 자동 보장하지 않는다.

코퍼스 1,024개는 모든 분할의 검색 인덱스에 그대로 둔다. holdout 정답 문서를 인덱스에서 빼는 실험이 아니다. 이번 holdout은 **새 질문에 대한 모델 미실행 분할**이며, 이전에 모델이 전혀 본 적 없는 FAQ 지식이나 작성자에게 숨긴 문제라는 뜻도 아니다.

구조 선택은 development, 임계값 피팅은 calibration, 고정한 구조의 마지막 평가는 holdout에서 한다. 사용자 선택한 NO_FAQ/FAQ macro-F1 최대 및 동률 시 FAQ 오거절 최소 기준을 유지한다. 대조 변형은 클래스별 연결 그룹의 총 가중치를 동일하게 맞추고 행 단위 지표도 함께 제시한다. LONG_QUERY/TYPO는 현재 양성 대조만 있으므로 이진 임계값 피팅에서 제외하고 별도 견고성 평가로 보고한다. 기존 v1 임계값은 v2에 피팅한 값이 아니다.

## 채점과 입력 계약

`dataset.py`는 사실별 허용 FAQ를 사용해 Hit / FactRecall / AllFactsHit / MRR를 계산한다. `score_case(..., k=10)`은 실제 최종 10개 문서를 대상으로 한다. C의 A+B 합집합 전체는 별도 `CandidateRecall@K_per_view`로 보고해야 한다. 합집합 20~40개를 다른 구조의 최종 Top10과 같은 예산으로 표시하면 안 된다.

`binary_calibration_target`은 `corpus_presence`와 `context_support`를 구분한다. 코퍼스에 답이 있어도 실제 검색된 문서에 근거가 없으면 후자의 목표값은 0이다. PARTIAL의 지원 가능한 사실을 전부 찾아도 전체 요청이 완전히 답변 가능해진 것은 아니다.

일반 검색·특수 통제·문맥·답변 가능성 트랙은 분리해서 보고한다. 트랙별 row-micro, 목적 macro, 분야 macro, 그룹 macro와 분모를 함께 기록한다. 비교 신뢰구간은 연결 그룹을 엔진 사이에 동일하게 재표집하는 paired bootstrap을 사용해야 한다. 현재 코드는 데이터 및 기본 채점 어댑터이며, 새 모델 결과나 신뢰구간을 산출한 상태는 아니다.

`data/inputs/*.jsonl`에는 `case_id`와 실제 검색 입력 `query`만 있다. 정답 FAQ·사실·분야·목적·코퍼스 상태는 모델에 전달하지 않는다. 원래 사용자 발화와 재작성은 라벨 파일에 보존한다. 사용자가 요청한 후보 로그 필드와 A/B 순위, rank_delta는 기존 측정 코드에 유지돼 있으며 이번 작업은 과거 로그를 수정하지 않았다.

## 재현 및 검수

이 폴더에서 Python 표준 라이브러리만으로 실행한다. Docker나 GPU가 필요 없는 데이터 작업이다.

```powershell
python -X utf8 build_dataset.py
python -X utf8 test_dataset.py
python -X utf8 dataset.py --split development --allow-unreviewed
```

세 번째 명령은 미검수 진단용 로드다. `--allow-unreviewed` 없이 실행하면 독립 검수 미완료 문항을 차단한다. V1의 `run_all.ps1`은 여전히 V1 회귀 실험이므로 이 파일만 바꾸어 v2를 측정했다고 보고하면 안 된다. 다음 서빙 실행은 v2 로더와 분할을 명시적으로 연결해야 한다.

검수자는 `review/index.html`의 질문·사실·원문 근거 및 전체 `review/corpus.html`을 확인한 뒤 `review/decisions.jsonl`에 `decisions.example.json` 형식으로 판정을 남긴다. 작성자의 재검토를 독립 검수라고 기록하지 않는다. NO_FAQ/PARTIAL은 전체 코퍼스에서 핵심 답의 부재를 의미적으로 검토해야 하며, 키워드 검색 결과 0건은 증명이 아니다. 대체 정답이 추가되면 사실·분할·해시를 다시 고정하고 이전 검수 판정은 재확인한다.

15개 자동 검증은 해시, 원문 근거 포함, 입력 분리, 분할 누수, 쌍의 사실 동일성, 상태 구분, 지표 계약, 검수 차단, calibration 전용 행 선택과 그룹 가중치를 확인한다. 문맥 재작성 문항도 일반 이진 피팅에서 제외해 별도 트랙으로 보고한다. `calibration_examples`가 이 제외 기준과 그룹별 총 가중치 1을 적용한다. 언어 동등성이나 사실 해석이 맞는지의 독립 의미 검수는 별개다. `data/manifest.json`은 작성본 고정 기록이고 공식 승인 기록이 아니다.

## 남은 한계

실제 사용자 실패 로그·날짜가 있는 정책 변경 이력이 없어 REAL_FAILURE/TEMPORAL_VERSION을 지어내지 않았다. DOCUMENT_ATTACK은 별도 문서·생성 실험으로 남겨 일반 검색 정확도에 섞지 않는다. 개인 조회 도구 실행과 생성 정답성도 여기서 측정하지 않는다.

긴 질문은 175~212자 규모의 서로 다른 배경 문장이다. 8K 토큰 장문이나 리랭커 다중 창 경계 스트레스 검증은 아니다. 숫자 경계 쌍은 같은 FAQ가 정답인 경우가 있으므로 같은 근거를 검색했다는 결과만으로 수치 추론이 옳다고 주장하지 않는다. 영어·혼합은 긍정/부재 양쪽에 있지만 약어·음역의 세부 범위는 제한적이다.

합성 문항, 동일 작성자, 제안된 대체 정답과 부재 라벨이라는 한계는 남는다. NO_FAQ의 서로 다른 부재 후보는 34개이며 calibration/holdout은 각각 9/8개뿐이다. 독립 검수와 추가 실측 없이 이 자료로 운영 임계값의 안정성을 보장하지 않는다.
