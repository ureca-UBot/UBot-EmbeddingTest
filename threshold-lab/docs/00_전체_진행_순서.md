# 임계값 결정 실험 — 전체 진행 순서

대상: `CHAT_CONFIDENCE_THRESHOLD`(T1, 질문 벡터 기준) / `FAQ_SENTENCE_SIMILARITY_THRESHOLD`(T2, 답변 문장 기준)
기한: 2026-10-27(화). 기존 분석 테스트·코퍼스·보고서의 규칙은 쓰지 않습니다.

## 파일 구성

| 파일 | 용도 |
|---|---|
| `docs/01_질문_작성_안내서.md` | 질문을 쓰는 팀원에게 나눠 주는 안내서 |
| `docs/02_라벨링_안내서.md` | 정답 FAQ와 필요한 문장을 붙이는 사람용 안내서 |
| `templates/questions_template.csv` | 질문 입력 양식 |
| `templates/weights.json` | 손해 가중치 (데이터를 보기 전에 확정) |
| `java/ThresholdScoreCollector.java` | 점수 수집 테스트 (새 패키지에 복사해서 사용) |
| `analysis/threshold_lab.py` | 라벨 시트 생성, 격자 탐색, 부트스트랩, 최종 채점 |
| `analysis/selftest.py` | 분석 스크립트가 제대로 계산하는지 합성 데이터로 확인 |

## 지켜야 할 약속

1. **`weights.json`은 dev 분석 전에 확정**합니다. 결과를 본 뒤 바꾸면 결과에 맞춘 선택이 됩니다. 스크립트가 실행할 때마다 파일의 해시를 출력합니다.
2. **final(최종 세트)은 후보 3쌍을 정한 뒤 한 번만** 봅니다. 결과가 마음에 안 들어도 후보를 바꿔 다시 final을 보지 마세요. 그렇게 하면 최종 세트가 개발 세트가 됩니다.
3. 수집하는 동안 **FAQ를 수정·추가하지 않습니다.** `meta.txt`의 FAQ 개수·최대 ID가 수집 시작과 끝에 같은지 확인합니다.
4. 시맨틱 캐시(`FAQ_CACHE_ENABLED`)와 Reranker(`FAQ_RERANK_ENABLED`)는 끈 상태로 측정합니다. 수집 테스트는 두 기능을 거치지 않고 검색과 문장 점수를 직접 호출하므로, 설정과 상관없이 영향이 없습니다.
5. 임베딩 서버는 **시연·운영과 같은 것**(Ollama 또는 vLLM)으로 수집합니다. `meta.txt`에 기록됩니다.
