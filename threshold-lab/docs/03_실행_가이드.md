# 실행 가이드 (PowerShell 기준)

작업 폴더는 `UBot-BE` 프로젝트 루트라고 가정합니다. 분석 스크립트는 어디에 두어도 됩니다 (아래는 `threshold-lab\tools\`).

## 0. 준비 (한 번)

```powershell
python -m pip install numpy pandas matplotlib
python threshold-lab\tools\selftest.py        # 마지막 줄이 ALL OK 이면 분석 도구 정상
```

- `threshold-lab\` 폴더(질문·라벨·수집 결과)에는 질문 원문이 들어갑니다. 코드 저장소에 올라가지 않게 `.git\info\exclude`에 `threshold-lab/`을 추가하세요.
- 수집용 테스트 파일은 `src/test/java/com/ubot/thresholdlab/ThresholdScoreCollector.java`로 복사합니다. `RUN_THRESHOLD_LAB=true`일 때만 실행되므로 평소 테스트에는 영향이 없습니다. 저장소에 올릴지는 팀에서 정하세요.

## 1. 질문 합치기

```powershell
python threshold-lab\tools\threshold_lab.py mergequestions q_a.csv q_b.csv q_c.csv --out threshold-lab\questions.csv
```

group/표현 유형 코드 오류가 있으면 파일과 질문을 알려 주며 멈춥니다. 완전히 같은 질문은 자동으로 제거됩니다.

## 2. 점수 수집

수집 전 확인:
- **스냅샷을 복원한 로컬 DB**에 연결되어 있는가 (공유 DB 금지: 앱이 통째로 뜨면서 스케줄러가 돌 수 있음)
- 임베딩 서버가 시연·운영과 같은 종류인가 (`.env`의 `AI_MODE` 등)
- 수집이 끝날 때까지 FAQ를 수정하지 않는다

```powershell
$env:RUN_THRESHOLD_LAB = "true"
$env:THRESHOLD_LAB_QUESTIONS = "threshold-lab/questions.csv"
$env:THRESHOLD_LAB_OUT = "threshold-lab/data"
.\gradlew.bat test --tests "com.ubot.thresholdlab.ThresholdScoreCollector" -i --rerun
```

끝나면 `threshold-lab\data\`에 `candidates.csv`, `sentences.csv`, `faq_catalog.csv`, `errors.csv`, `meta.txt`가 생깁니다.
`meta.txt`의 `FAQ변경여부=없음`을 확인하세요. `errors.csv`에 줄이 있으면 해당 질문만 다시 수집해야 합니다.

## 3. 라벨링

```powershell
python threshold-lab\tools\threshold_lab.py labelsheet --questions threshold-lab\questions.csv --data threshold-lab\data --out threshold-lab\label_sheet.csv
```

`label_sheet.csv`와 `data\faq_catalog.csv`를 두 사람에게 따로 나눠 주고(서로 보지 않게), 각자 `labels_a.csv`, `labels_b.csv`로 채워 받습니다 (`02_라벨링_안내서.md`).

```powershell
python threshold-lab\tools\threshold_lab.py merge --a threshold-lab\labels_a.csv --b threshold-lab\labels_b.csv --out threshold-lab\labels_final.csv
```

`status`가 `CONFLICT`인 줄은 `final_label`, `final_gold_faq_ids`를 합의해서 채우세요.

## 4. 필요한 문장 라벨

```powershell
python threshold-lab\tools\threshold_lab.py sentencesheet --labels threshold-lab\labels_final.csv --data threshold-lab\data --out threshold-lab\sentence_sheet.csv
```

`needed` 열에 `Y`/`N`을 채운 파일을 `sentence_labels.csv`로 저장합니다. (이 단계를 건너뛰면 '불완전 전달'은 판정하지 않고 분석만 진행됩니다.)

## 5. 개발 세트 분석 → 후보 3쌍

`prior-answerable`은 실제 사용자 질문 중 FAQ로 답할 수 있는 비율입니다. `question_log`에서 최근 질문을 표본으로 보고 추정하세요. 모르면 기본 0.75를 쓰되 보고서에 근거 없는 가정이라고 적으세요.

```powershell
python threshold-lab\tools\threshold_lab.py dev --labels threshold-lab\labels_final.csv --data threshold-lab\data --sentence-labels threshold-lab\sentence_labels.csv --weights threshold-lab\weights.json --prior-answerable 0.75 --out threshold-lab\out
```

산출물 (`threshold-lab\out\`): `dev_report.md`, `dev_candidates.json`, `grid_dev.csv`, `t1_view.csv`, `t2_view.csv`, `loss_heatmap.png`, `score_distributions.png`

`prior-answerable`과 `weights.json`을 바꿔 가며 후보가 얼마나 움직이는지 보는 것(민감도 확인)은 괜찮습니다. 다만 기준 선택은 이 두 값을 **분석 전에** 정해 둔 것으로 하세요.

## 6. 최종 세트 채점 (한 번만)

```powershell
python threshold-lab\tools\threshold_lab.py final --labels threshold-lab\labels_final.csv --data threshold-lab\data --sentence-labels threshold-lab\sentence_labels.csv --weights threshold-lab\weights.json --prior-answerable 0.75 --candidates-json threshold-lab\out\dev_candidates.json --out threshold-lab\out
```

두 번째 실행은 막힙니다. 후보를 바꿔 다시 보면 최종 세트가 개발 세트가 되기 때문입니다.

## 7. 값 반영

`.env` 또는 배포 환경 변수에 반영합니다.

```
CHAT_CONFIDENCE_THRESHOLD=<T1>
FAQ_SENTENCE_SIMILARITY_THRESHOLD=<T2>
```

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| 테스트가 `JWT_SECRET` 등을 못 찾음 | 프로젝트 루트의 `.env`가 읽히는지 (로컬 프로필은 `file:.env`를 읽음) |
| 후보가 0건 | 현재 임베딩 프로필(`meta.txt`의 프로필ID)에 질문 벡터가 있는지, DB가 스냅샷으로 복원되었는지 |
| 문장 점수가 비어 있음 | `sentences.csv`가 비어 있으면 로그 가로채기가 안 된 것입니다. 로깅 설정이 `FaqSentenceFilterService`의 debug를 막고 있지 않은지 확인 |
| 한글이 깨짐 | 엑셀에서 저장할 때 CSV **UTF-8**로 저장 |
